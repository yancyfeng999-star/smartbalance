# 浏览器导入无反馈修复验收

## 范围与验收

- Standard 模式：只处理智余的浏览器导入、保存结果和对应设置 UI，不修改其他产品。
- 点击「从 Chrome 导入并添加」有持续可见的进度/结果；失败不清草稿，不添加空账号。
- 区分浏览器不存在、目录访问被拒绝、数据读取失败、未找到平台登录态、钥匙串失败。
- 目录权限不足时提供系统目录选择入口；取消不修改原账号。单个 Profile 选择不跨账号混合导入。
- 保存密钥失败不宣称成功；不记录或公开凭据。

## 0.4.3 漏验与根因

用户反馈发生在已安装的 0.4.3（build 87），不是未更新。应用日志证明点击已经到达导入方法，但返回“未找到 Chrome / Edge”。同时本机 Chrome 用户目录和 Cookie 数据库实际存在。

macOS 系统日志在相同点击时间记录 `kTCCServiceSystemPolicyAppDataDetailed` 拒绝访问，并记录当前应用签名不匹配之前的授权要求。发行包为 ad-hoc 签名；不能假定升级后沿用上个构建的系统授权。

代码使用 `try? contentsOfDirectory` 把目录读取失败吞掉，`fileExists` 又把不可访问数据库当成不存在，最终误报浏览器不存在。设置导入按钮附近没有结果区域；首页 banner 会自动消失，用户看到“点击没反应”。上一轮 CLI 导入和 Provider 查询通过，**没有覆盖正式 App 身份下的 macOS 目录权限与完整按钮链路**。

另外，新账号按钮在异步任务开始前清空草稿；保存方法不返回成功状态，导入方法会无条件覆盖密钥保存失败为成功提示。

现场补做重启后发现：旧 ad-hoc 构建创建的普通 Keychain 条目，`SecItemUpdate` 可以返回成功，但原读取 ACL 仍拒绝当前构建。内存缓存掩盖了不可读取性，导致导入当次有余额、重启后又显示待补。此项失败后暂停发布，补修并重新验收。

## 最小修复

- Infrastructure：显式处理目录/文件读权限及读取错误；接受用户明确选定的 Chrome / Edge 根目录或单个用户目录；拒绝宽泛/无关目录，限制访问范围。
- AppModel：保留每个平台的导入消息；权限不足后提供非阻塞系统文件夹选择窗口；选定资源的访问范围仅覆盖该次导入，不保存书签。
- APIAccountsSection：按钮旁显示进度与结果；捕获点击时草稿，仅在账号保存成功后清空；原账号重新导入时保留编辑区反馈。
- 保存方法返回 Bool，导入失败/取消/密钥保存失败均不提示成功。
- 重新保存采用新凭据引用，写入后直接从 Keychain 读回核对，再原子保存账号配置；不覆盖或删除原条目。MiniMax 的 token 和组织 ID 在同一次保存中更新。
- 已有账号与新增账号的权限按钮采用不同文案和稳定辅助功能标识。
- 不扩大到全盘访问、系统权限修改、签名证书替换或浏览器文件写入。

## 验证记录

- 先运行目录权限回归测试：4 条中 2 条失败，准确复现 POSIX/Cocoa 权限错误被吞掉。
- 修复后 10 条目录访问测试通过：权限拒绝、底层权限错误、真正缺失、其他读取失败、多 Profile、单 Profile、Chrome/Edge 目录选择、宽泛目录拒绝。
- 完整测试：**398 passed / 0 failed**（Domain 98 + Infrastructure 264 + App 36），含 10 条目录访问及 3 条保存读回回归；`TEST SUCCEEDED`。
- 真实 App UI：权限被拒绝时显示具体错误；系统目录选择取消后草稿名称保留、账号数不变；确认 Chrome 目录后成功添加 MiniMax；APINebula 对原账号重新导入，未重复添加。
- 软件与实时 Chrome 网页核对：MiniMax 人民币钱包 **¥394.91**，APINebula 人民币钱包 **¥199.47**。二者刷新及最终构建干净退出/重启后均仍显示一致余额，无需再次导入。
- 使用本地 Debug 验收副本（独立 bundle ID、临时普通窗口），真实设置中仅操作这两个授权平台。其他账号因副本代码身份不同显示待补，不代表用户安装版数据丢失，未重写其他渠道凭据。临时窗口/启动策略源码已还原，不进入发行包。
- Release 包与远端发布结果在完成后补录；未完成前不宣称通过。

## 安全与限制

- 不记录 Cookie、Token、Safe Storage 密码、原始响应或用户设置文件。
- 系统目录选择是 [Apple 推荐的明确文件访问方式](https://developer.apple.com/videos/play/wwdc2023/10053/)，不是绕过 macOS 隐私限制。
- 目录授权和浏览器钥匙串授权独立；拒绝任一授权都必须准确显示失败，不无限自动重试。
- 不更换用户安装版 App；真实第二个登录账号及跨 macOS 设备仍需单独验证。未退出用户 Chrome 登录来制造失效；失效/查询失败保留余额与时间通过已有模拟测试覆盖，不称为真实失效验收。
- ad-hoc 构建更新可能仍要求在新版本重新导入/填写一次；已验证同一最终验收构建重启持久化，不承诺跨签名自动继承。旧 Keychain 条目保留，不降低 ACL，不改成明文存储。
- 发包采用 `CLEANUP_PROJECT_ONLY=1 SKIP_DMG_LAYOUT=1`；不操作 Finder、不删除桌面或全局 DerivedData、不弹出非本次打包卷。
- 未配置 GitHub CI；本地测试/构建不称为 CI 通过。未独立复核。
