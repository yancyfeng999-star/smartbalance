# Bytebroad 钱包与浏览器重新连接

日期：2026-10-21。模式：Standard，凭据和发布严格门禁。

## 需求与边界

- 增加 Bytebroad 人民币钱包余额、累计消费、报警及现有天/周/月用量统计。
- 类似 MiMo：从 Chrome / Edge 导入已登录会话，用户不必抄写 Cookie 或 UID。
- 登录失效时显示明确提示；提供打开官网登录和“登录完成，重新连接”按钮。
- 浏览器目录访问被拒绝与网站未登录分别处理；首次目录授权仍由系统选择窗口完成。
- 不改智额、不创建平台 API Key、不充值、不改系统隐私或全盘权限、不改签名或普通 Keychain 策略。

## 已核对的接口契约

- 官网：`https://token.bytebroad.com.cn`；钱包：`/wallet`。
- 钱包查询：`GET /api/user/self`；使用该域的 `session` Cookie 与 `New-Api-User`。
- `data.quota` 为钱包余额，`data.used_quota` 为累计消费；官网 `/api/status` 的 `quota_per_unit=500000`、`quota_display_type=CNY`、`usd_exchange_rate=1`。
- 仅为此固定站点采用上述换算，不把套餐、积分、当日调用或其它 New-API 站点的单位混入钱包。
- 不保存真实响应、账号资料或会话值作为测试 fixture。

## 实现步骤

1. 先补渠道配置与浏览器发现失败测试，确认旧实现无法满足。
2. 增加 Provider、注册、固定官网配置、Cookie 导入与标识字母回退图标。
3. 增加结构化登录失效标记；保留失败前的余额和成功更新时间；网络/解析失败不提示重新登录。
4. 连接入口常驻账号卡，不要求先展开手动密钥编辑器；登录后由用户点击重新连接，不后台轮询或自动打开网站。
5. 仅在用户已启用且系统已授权通知时提醒登录失效，每次运行中同一账号恢复前最多一次；未授权时保留应用内提示。
6. 同次会话记住所选浏览器目录，重新连接优先使用；不新增持久化目录授权书签。
7. 验证、更新开源与隐私文档、正式打包、PR 合并 main、发布 GitHub Release、回查资产及更新器。

## 最小安全评估

数据流：用户点击连接 → 仅目标平台 Cookie → 进程内凭据 → 普通 Keychain → 固定 HTTPS 钱包接口 → 非敏感余额快照和用量历史。

| 风险 | 控制 | 验证 |
| --- | --- | --- |
| 会话泄露到自定义站点 | 固定官方请求主机；忽略非官方 baseURL；禁止重定向携带会话 | 请求目标测试 |
| 日志或 fixture 泄露 | 只输出通用错误；不输出响应正文、Cookie、Token、账号资料 | 错误脱敏测试及差异审查 |
| 跨浏览器/账号串用 | 同一平台、域名及用户目录内取会话，响应账号标识核对 | 域名/账号测试 |
| 失败导致余额或用量被清空 | 沿用最后成功快照与时间；失败不采样 | 刷新回归测试 |
| 反复弹窗/后台读取 | 用户明确点击；权限拒绝只引导目录选择；无登录自动化或认证弹窗变更 | 连接及取消验收 |
| 验收副本污染应用列表 | 构建置于 `.noindex`；只注销本次产物；保留正式 App 和已有归档 | 索引前后检查 |

依赖：不新增第三方依赖，沿用现有 HTTP、Keychain、CommonCrypto、AppKit 与锁定的 MenuBarExtraAccess。漏洞扫描未配置，不宣称无漏洞。

## 验收

- 正常导入、余额刷新、零余额、无当天使用记录、401/403、业务拒绝、5xx、超时、取消、金额缺失/无效、账号不匹配均有测试。
- 单元测试只使用虚构数据；实时钱包与网站的核对单独记录，不公开真实账户数据。
- 授权取消和导入失败保留原账号及表单；浏览器不可读不误报未登录。
- 构建与打包不覆盖用户安装版；副本不留在系统搜索中。
- 测试、真实接口、真实 UI、发布、更新器与用户安装分别记录；不能互相替代。
